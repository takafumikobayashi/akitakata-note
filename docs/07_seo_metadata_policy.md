# SEO・メタデータ方針（改訂版）

## 1. 文書の目的

本書は、「あきたかたノート」における検索流入、共有流入、メタデータ整備の方針を定めるものである。
本サイトは、地図・季節・テーマによる探索体験を重視する一方で、主対象ユーザーである「外から安芸高田市に興味を持つ人」に届くためには、検索エンジンやSNS共有から個別ページへ自然に着地できる構造を初期から持つ必要がある。

また、本サイトは日本語中心で運用するが、固定ページや基本導線については将来的に限定的な英語対応を持ちうる。
そのため、本書では日本語中心のSEOを前提としつつ、将来的な限定的多言語展開を阻害しないメタデータ設計の方向性も整理する。

本書の目的は以下の通りである。

* 検索UIの有無とは別に、検索流入に耐える公開構造を定義する
* OGP、title、description、構造化データ、サイトマップ等のMVP要件を整理する
* 情報設計書、技術設計概要、コンテンツ運用設計の前提を揃える
* 個人運営サイトとしての表現方針と、検索・共有時の見え方を整合させる
* 日本語中心の運用を前提にしつつ、限定的な英語ページ追加を阻害しない構造を意識する

⸻

## 2. 基本方針

### 2-1. 検索UIと検索流入は分けて考える

本サイトは、初期段階でサイト内全文検索UIを持たなくてもよい。
一方で、検索エンジンからスポット名、地名、行事名、季節の風景などをきっかけに個別ページへ到達できることは、MVP段階から重要である。

### 2-2. 人には探索的に、機械には階層的に

本サイトは人にとっては「探索しやすい」構造を目指す。
一方で検索エンジンに対しては、一覧、個別ページ、テーマページ、季節ページなどの辿りやすい階層構造を持たせる。

### 2-3. すべての公開ページに役割を持たせる

個別投稿、一覧、テーマ別、季節別、Aboutなど、公開されるページはそれぞれ意味のある着地ページとして設計する。
検索や共有で訪れた人が、そのページ単体でも最低限の文脈を理解できる状態を目指す。

### 2-4. 誇張よりも整った文脈を優先する

SEOのために過度に刺激的なタイトルや説明文をつけるのではなく、写真・場所・時期・内容が適切に伝わる、自然で信頼できる文面を優先する。

### 2-5. 個人運営・非公式性を崩さない

検索結果やSNS共有時にも、行政公式や観光協会公式と誤認されるようなタイトル・説明文・OGP表現は避ける。
信頼性は確保しつつ、非公式の個人運営メディアとしての距離感を保つ。

### 2-6. 多言語SEOは段階的に考える

MVPでは日本語中心のSEOを主軸とし、全投稿の多言語SEOは前提にしない。
一方で、トップページ、Aboutページ、固定ページ等について将来的に限定的な英語版を持つ可能性があるため、URL、メタデータ、構造化データの設計はその拡張を阻害しないことが望ましい。

⸻

## 3. SEOの目的と到達イメージ

### 3-1. MVPで実現したいこと

MVPで実現したいのは、次のような状態である。

* 投稿詳細ページが、地名・スポット名・季節キーワードなどで検索エンジンに認識されやすい
* SNS共有時に、写真・タイトル・説明が自然に表示される
* サイト全体の更新内容がサイトマップ経由で伝わる
* 個別ページからテーマや関連投稿へ遷移しやすい
* トップページ以外から入ってもサイトの文脈がわかる
* 固定ページや基本導線については、将来的な英語ページ追加に拡張しやすい

### 3-2. 初期段階で狙う流入の種類

MVPでは、以下のような流入を主に想定する。

* 地名検索
    例: 安芸高田 ○○
* スポット名検索
    例: ○○神社 安芸高田
* 季節ワード検索
    例: 安芸高田 桜 / 紅葉 / 神楽
* SNSで共有された投稿からの流入
* 将来的な再訪のためのブックマーク流入
* 固定ページ経由の限定的な英語導線からの流入余地

⸻

## 4. 対象ページ種別

本サイトでは、少なくとも以下のページ種別を検索・共有の対象として考える。

### 4-1. トップページ

サイト全体の入口。
サイトのコンセプトと新着・主要導線が分かるようにする。

### 4-2. 投稿詳細ページ

最重要の着地ページ。
1投稿ごとに固有URLを持ち、写真・場所・時期・短い文脈・関連導線を含む。

### 4-3. 一覧ページ

新着一覧やアーカイブ一覧。
探索の補助線であり、検索エンジンにとってもページ群の関係を示す。

### 4-4. 季節別ページ

春・夏・秋・冬など、季節のまとまりを示すページ。
同じ場所の異なる表情や季節ごとの魅力を伝える。

### 4-5. テーマ別ページ

自然、文化、日常、イベント等のテーマごとの一覧ページ。
ユーザーの関心文脈に沿った入口になる。

### 4-6. Aboutページ

このサイトの目的と個人運営であることを示す。
ブランド理解、信頼性、誤認防止の観点で重要。

### 4-7. 固定ページの英語版（将来拡張）

MVPでは必須ではないが、将来的にトップやAbout等の固定ページに限定的な英語版を持つ可能性を考える。
その場合、それらも検索・共有対象ページとして成立するように設計する。

⸻

## 5. title / description 方針

### 5-1. 基本原則

* ページごとに固有の title を持つ
* 簡潔で自然な日本語を優先する
* 場所・内容・サイト名が分かるようにする
* 公式性を示唆する語は使わない
* 誇張や過度な煽りを避ける
* 将来的に英語版を持つ場合でも、各言語で自然な文面を個別に持てる構造が望ましい

### 5-2. 投稿詳細ページの title 方針

基本形は以下のようにする。

{投稿タイトル} | あきたかたノート

タイトルがない軽量投稿の場合は、以下のように補完する。

{場所名}の{簡易要約} | あきたかたノート

望ましい例

* ○○神社の春の参道 | あきたかたノート
* 雨上がりの川辺を歩く | あきたかたノート
* ○○地区から見た夕景 | あきたかたノート

避けるべき例

* 安芸高田市公式 ○○
* 絶対行くべき○○
* 完全ガイド ○○

### 5-3. 一覧・テーマ・季節ページの title 方針

一覧・テーマ・季節ページは、何のまとまりなのかが分かるようにする。

例

* 新着投稿 | あきたかたノート
* 春の風景 | あきたかたノート
* 文化 | あきたかたノート
* 自然の投稿一覧 | あきたかたノート

### 5-4. description 方針

description は、検索結果や共有時にページの中身が自然に伝わる短い説明とする。
検索対策としてキーワードを詰め込みすぎず、閲覧者に意味が通ることを優先する。

投稿詳細ページ

以下を簡潔に含める。

* 写真の主題
* 場所
* 時期
* その投稿で見られる内容

サイトトップ

* 安芸高田市の“いまの空気”と“暮らしの解像度”を伝える個人運営のローカルメディア

のような説明を基本とする。

固定ページの英語版（将来）

英語版を作る場合は、日本語 description の直訳ではなく、英語話者に自然な短文として別管理することが望ましい。

⸻

## 6. OGP方針

### 6-1. 基本方針

* 全公開ページに OGP を付与する
* タイトル、説明文、画像の最低限を揃える
* 個人運営サイトであることと、コンテンツ内容が自然に伝わることを重視する
* 行政公式と誤認される文言は避ける
* 将来的に英語固定ページを持つ場合は、そのページ固有の言語に応じたOGP文面を持てることが望ましい

### 6-2. OGP画像

基本方針

* 投稿詳細ページでは、その投稿の代表画像を使う
* トップページやテーマページでは、固定画像または代表ビジュアルを使う
* 写真が強みであるため、画像の見え方は重要な要素とする

注意点

* 顔や私有情報が目立つ画像をそのままOGPに使わない
* 小さな文字を多く載せた画像にしない
* 行政資料やバナーのようなデザインは避ける

### 6-3. OGPのタイトル・説明文

OGPのテキストは、基本的に title / description と整合させる。
ただし、共有時の見え方を踏まえて読みやすさを優先して微調整してよい。

⸻

## 7. 構造化データ方針

### 7-1. 目的

構造化データは、検索エンジンにページの意味を伝えやすくするために使う。
MVPでは、複雑な設計よりも、基本的な型を安定して付与することを優先する。

### 7-2. MVPでの対象

MVPでは、主に以下を対象とする。

* 投稿詳細ページ
    → Article 系
* 場所性が強い投稿
    → Place 相当の情報も持たせることを検討
* サイト全体
    → WebSite / Person 相当の基本情報を検討

### 7-3. 基本方針

* 投稿ごとに固有情報を持たせる
* タイトル、概要、公開日、画像、URL 等を反映する
* 場所情報がある場合は、無理のない範囲で位置情報や名称を反映する
* 構造化データは事実ベースで扱い、誇張表現を入れない

注意点

個人運営サイトであることから、Organization 的に強く見せすぎない。
必要に応じて Person または WebSite ベースの扱いを優先する。

将来拡張

英語固定ページ等を持つ場合は、構造化データでもそのページ言語とURLの整合を取れることが望ましい。

⸻

## 8. サイトマップ / robots 方針

### 8-1. サイトマップ

MVPから sitemap.xml を生成する。
対象は以下を基本とする。

* トップページ
* 投稿詳細ページ
* 主要一覧ページ
* テーマページ
* 季節ページ
* About等の公開固定ページ

方針

* 公開ページのみを含める
* 下書きや非公開ページは含めない
* URL変更がある場合は速やかに反映される構成が望ましい
* 将来的に英語固定ページを持つ場合は、それらも適切に含められる構造が望ましい

### 8-2. robots.txt

robots.txt を整備し、公開対象と管理系ページを明確に分ける。

方針

* 公開ページはクロール可能
* 管理ページ、下書きプレビュー、内部用途URLはクロールさせない
* 技術構成に応じて追加の制御を行う

⸻

## 9. URL方針

### 9-1. 基本方針

URLは、将来的な資産性を考慮して安定的で意味が分かりやすい構造にする。
検索流入・共有・再訪を考えると、後から大きく変わりにくい方が望ましい。

### 9-2. 投稿URL

投稿は固有URLを持つ。
スラッグは、できるだけ人が読んで意味が分かる形が望ましい。

方針

* 自動IDのみのURLは避ける
* タイトルベースまたは場所＋要約ベースのスラッグを検討する
* 日本語URLの是非は技術設計で判断するが、共有性と運用性を優先する

### 9-3. 一覧 / テーマ / 季節URL

* /posts
* /theme/{slug}
* /season/{slug}

のような階層的構造を基本に考える。

方針

* 人にも意味が分かる
* 機械にも構造が読み取りやすい
* 今後の拡張でも破綻しにくい

### 9-4. 将来的な英語固定ページURL

MVPでは必須としないが、将来的に英語版固定ページを持つ場合は、以下のようなロケールベースURLへ拡張可能であることが望ましい。

* /en/about
* /en/...

ただし、全投稿に対するロケール分岐はMVPでは前提にしない。

⸻

## 10. 内部リンク方針

### 10-1. 投稿詳細からの導線

投稿詳細から、関連投稿、場所、季節、テーマへのリンクを持たせる。
検索エンジンにとっても、ページ同士の関係が分かりやすくなる。

### 10-2. 一覧・テーマページからの導線

一覧やテーマページから個別投稿へ遷移しやすくする。
また、テーマページ同士・季節ページ同士の関係は整理しすぎず、過剰リンクを避ける。

### 10-3. About等への導線

すべての公開ページから、Aboutやフッターを通じてサイトの性質が分かるようにする。
信頼性と誤認防止の観点でも重要である。

### 10-4. 固定ページの英語導線

将来的に英語固定ページを持つ場合は、日本語ページとの関係がわかりやすく、かつ機械にも解釈しやすい内部リンク構造を持つことが望ましい。

⸻

## 11. 運用面での方針

### 11-1. 投稿タイトルの付け方

投稿タイトルは、検索流入だけを意識したものではなく、内容が自然に伝わるものを優先する。
必要以上にSEO語を詰め込まない。

### 11-2. description の生成

description はAIやテンプレートで補助生成してよいが、人が確認する前提とする。
軽量投稿では本文不足が起きやすいため、description は特に補助生成の価値が高い。

### 11-3. OGP確認

主要ページについては、共有時の見え方を確認する。
タイトル、説明文、画像が意図通りかをレビューする運用を持つことが望ましい。

### 11-4. 限定的英語ページの運用

英語固定ページを持つ場合は、機械翻訳の自動公開を前提にせず、AI翻訳ドラフトを人が確認したうえで公開する運用が望ましい。
全投稿を英語化することは前提にしない。

⸻

## 12. 公私区分との関係

SEO・メタデータの設計は、単なる流入設計ではなく、誤認防止設計 にも関係する。
特に以下は、公私区分・対外表記方針と整合させる必要がある。

* トップページの description
* OGP説明文
* Aboutページの title / description
* SNS共有時の見え方
* サイト名の見え方
* 公式情報リンク時の文言

SEOを優先するあまり、結果的に行政公式や公認サイトのように見える表現は避ける。

⸻

## 13. 現時点でのMVP要件まとめ

MVPでは、最低限以下を含める。

* 投稿詳細ページごとの固有URL
* ページ単位の title / description
* OGP設定
* sitemap.xml
* robots.txt
* 基本的な構造化データ
* SNS共有時に自然に見えるタイトル・説明・画像
* 検索エンジンやSNS共有からの着地を意識した一覧・詳細構造
* 固定ページや基本導線について、将来的な英語ページ追加を阻害しない構造

一方で、以下はMVPでは必須としない。

* サイト内全文検索UI
* 高度なSEO分析基盤
* リッチスニペット最適化の作り込み
* RSS/Atom の本格運用
* 多言語SEO
* hreflang の本格運用

⸻

## 14. 今後の判断で参照すべき問い

* このページは、検索や共有で着地した人にも意味が伝わるか
* タイトルと説明文は自然で、誇張や誤認を招かないか
* この構造は、人には探索しやすく、機械には辿りやすいか
* OGPやメタ情報が、個人運営サイトとしての距離感を保てているか
* URLやページ構造は将来的な資産性を損なっていないか
* この多言語対応は、MVPに対して過剰ではなく、後から足せる構造になっているか
