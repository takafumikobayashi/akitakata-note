# ADR-0004 地図基盤

ステータス: **採用（Accepted）** — 2026-06-28 確定（MapLibre GL JS ＋ Protomaps/PMTiles on R2）

前提: `0001`（Next.js ＋ Cloudflare ＋ R2）採用済み。地図導線・公開レベル表示制御は `08 §5`・`14 §5-6`。

## 背景・要件

地図は主要導線である一方、位置情報リスクの入口でもある（`08 §5-4`）。地図基盤は表示制御を**こちらが完全に握れる**ことが重要。

* ピンは Place 単位、ピン位置は**撮影地点そのものではなく代表地点**。公開レベルに応じて表示を変える（`08 §5-2`、`14 §5-6`）:
  * A=正確な代表地点 / B=おおよそ（ぼかし/エリア）/ C=ピンなし・地名のみ / D=非表示。
* 少量投稿でも破綻しないUI（`14 §8`）。スマホ最適化。
* React（Next.js）親和。`0001` の Cloudflare/R2・低コストを活かす。
* ベンダーAPIキーや従量課金・利用規約上の制約をできるだけ避ける（個人運営・継続性）。

## 候補

1. **MapLibre GL JS ＋ ベクタータイル**（タイル源は Protomaps/PMTiles を R2 自己ホスト、または OpenFreeMap / MapTiler 等）
2. Google Maps JavaScript API
3. Mapbox GL JS
4. Leaflet ＋ ラスタータイル（OSM 等）

## 比較観点

| 観点 | MapLibre+ベクタ | Google Maps | Mapbox | Leaflet+ラスタ |
|---|---|---|---|---|
| ピン描画・表示制御の自由度（レベル別ぼかし） | ◎（自前レンダリング） | △（規約・部品制約） | ○ | ○ |
| APIキー/従量課金の回避 | ◎（PMTiles on R2 なら不要・¥0） | ✕ 必須・従量 | △ 無料枠超で従量 | ◎ |
| Cloudflare/R2 適合 | ◎（PMTiles を R2 配信・egress無料） | △ | △ | ○ |
| React/Next 親和 | ◎ react-map-gl 等 | ○ | ◎ | ○ |
| 見た目・ベクタ表現・軽さ | ◎ | ◎ | ◎ | △（ラスタ） |
| 規約上の位置情報配慮 | ◎（自前で完結） | △（外部送信） | △ | ○ |
| ベンダーロック | ◎ 無 | ✕ | △ | ◎ |

## 決定

**MapLibre GL JS ＋ Protomaps（PMTiles）を R2 に自己ホスト、を採用する。**

採用理由

* ピン描画を**自前でレンダリング**するため、公開レベル A〜D の表示制御（代表地点・ぼかし・ピンなし・非表示）を**完全に自分で実装**できる。安全方針（`08`）の「ピン≠撮影地点」「レベル別表示」を仕組みで担保できる。
* **PMTiles を R2 に置けば API キー不要・egress無料でほぼ¥0**。`0001/0003` の Cloudflare/R2 構成にそのまま乗る。
* オープンソースでベンダーロックなし。`react-map-gl`/MapLibre で Next.js と親和。
* 地図タイルの取得が外部サービスへのリクエストにならない（自己ホスト）ため、閲覧者の位置・行動が第三者地図ベンダーに渡りにくく、個人運営メディアの距離感（`05`）とも相性が良い。

## 見送り理由

* **Google Maps / Mapbox**: 高機能だが API キー・従量課金・利用規約があり、低トラフィック個人運営にはコストとロックが重い。ピン表示の自由度や位置情報の外部送信面でも本件の安全方針と相性が劣る。
* **Leaflet ＋ ラスタOSM**: 手軽でキー不要だが、ベクタ表現・ズーム品質・スタイル制御で MapLibre に劣る。将来の表現拡張余地が小さい。

## 影響

* `14 §5-6`: 地図UIの実装基盤が確定（MapLibre）。レベル別ピン制御を MapLibre のレイヤ/表現で実装。
* `12 §4-2 / §6`: Place の latlng・base_location_level・map_display を地図レンダリングが参照。**C/D や map_display=false はそもそも地図データに出さない**（クライアントに正確座標を渡さない実装）。
* `0003`: PMTiles も R2 配信に含める。

## 将来見直す条件

* PMTiles の生成・更新運用（安芸高田市周辺の地図データ整備）が個人運営として重いと判明 → OpenFreeMap / MapTiler 無料枠等のマネージドなベクタタイルへ。
* 高度な地図機能（経路・大量ピンのクラスタリング高度化等）が必要になった場合に再評価。
* 地図の表現要件が増え、商用タイルの品質が明確に必要になった場合（コスト影響を再評価）。

## 補足: 位置情報を「クライアントに渡さない」原則

公開レベル C/D の Place や `map_display=false` の投稿は、**地図用 API レスポンス自体に正確座標を含めない**。ぼかし（B）は、表示前にサーバ側で代表地点を粗くした座標のみを返す。クライアント JS に正確座標を載せて表示時に隠す、という実装は採らない（漏洩面の排除。`08 §11` の「安全をUIでなく構造で」と整合）。
