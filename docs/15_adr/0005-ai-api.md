# ADR-0005 AI補助 API

ステータス: **採用（Accepted）** — 2026-06-28 確定（Anthropic Claude API。既定 Haiku 4.5、品質重視時 Opus 4.8）

前提: `0001`（Next.js ＋ Cloudflare）、`0002`（D1）、`0003`（R2派生画像）採用済み。AI方針は `09_risk_ai_policy.md`、AIUsage は `12 §4-9`。

## 背景・要件

AIは**編集補助**であり代弁者にしない（`02` `09`）。用途は写真投稿に対する**タイトル・要約・タグ・カテゴリ（テーマ）案の生成**で、最終決定は人が行う（`12 §4-9` の AIUsage、human_review_level A/B/C）。

* **写真を読んで**提案するため、画像入力（vision）が要る。テキストは短文（メモ）。
* **低頻度・低volume**（個人運営、月数〜十数投稿）。1投稿あたり数回の呼び出し。
* 日本語の編集品質・トーン（「静かなギャラリー」）が出力品質に直結。
* `0001` の低コスト方針。ただしAI APIは外部呼び出しになる（Workersからでも）。
* **プライバシー**: AIへ送る画像は EXIF/GPS除去済みの派生（`0003`、`08 §11-4`）。GPS入り原本は送らない。
* APIキーはサーバ側のみ（Route Handler / Server Action）。クライアントに出さない。

## 候補

1. Anthropic Claude API（vision対応。既定 Haiku 4.5 / 品質重視 Opus 4.8）
2. OpenAI（GPT系）
3. Google Gemini（Flash系）
4. Cloudflare Workers AI（Llama等、Cloudflareネイティブ）

## 比較観点

| 観点 | Claude | OpenAI | Gemini | Workers AI |
|---|---|---|---|---|
| 日本語の編集品質・トーン適合 | ◎ | ○ | ○ | △ |
| 画像入力（vision） | ◎ | ◎ | ◎ | △（モデル限定・弱い） |
| 低volumeでのコスト | ◎（従量・極小） | ◎ | ◎ | ◎（最安・無料枠） |
| Cloudflare/サーバ実装の容易さ | ◎（HTTP/SDK） | ◎ | ◎ | ◎（ネイティブ） |
| 人間ゲート・履歴設計との相性 | ◎ | ◎ | ◎ | ○ |
| ベンダー中立性 | ○ | ○ | ○ | △（Cloudflare依存） |

## 決定

**Anthropic Claude API を採用。既定モデルは Claude Haiku 4.5（`claude-haiku-4-5`）、編集品質を重視する生成では Claude Opus 4.8（`claude-opus-4-8`）を選択的に使う。**

採用理由

* タイトル・要約・タグ案は短い生成・分類タスクで、**Haiku 4.5 が高速・低コスト**（$1/$5 per MTok）。低volumeなので月額はごく小さい。
* 日本語の編集ニュアンス・トーン適合が良く、`09` の「補助だが品質は保つ」方針に合う。品質を上げたい場面のみ **Opus 4.8**（$5/$25 per MTok）へ引き上げられる。
* vision対応で写真から直接提案でき、メモが薄い軽量投稿でも機能する。
* サーバ側（Route Handler / Server Action）から呼び、APIキーを秘匿。`12 §4-9` の AIUsage（used / targets / human_review_level）を D1 に記録。

実装方針

* 入力画像は **R2の派生（EXIF/GPS除去済み）** を渡す。原本（GPS入り）は送らない（`08 §11-4`、`0003`）。
* 出力は**提案**として人に提示し、人が採用/編集して確定（自動公開しない。`09`、`14 §9`）。
* AIUsage に使用対象（タイトル/要約/タグ/カテゴリ）と人の関与度（A:全面編集 / B:確認修正 / C:ほぼそのまま）を残す。
* モデルIDは確定値: 既定 `claude-haiku-4-5`、品質重視 `claude-opus-4-8`（日付サフィックスは付けない）。

## 見送り理由

* **OpenAI / Gemini**: いずれも能力的に妥当だが、日本語の編集トーン適合・本プロジェクトの方針との噛み合わせで Claude に対する明確な優位がなく、採用の決め手に欠ける。将来比較する余地は残す。
* **Cloudflare Workers AI**: スタックにネイティブで最安だが、日本語の編集品質と vision が用途（写真からの繊細な提案）に対して弱い。AIが「補助だが品質を保つ」という方針に届きにくい。→ コストを極限まで詰める必要が出た場合の補助用途として再評価。

## 影響

* `12 §4-9 AIUsage`: used / targets / human_review_level を D1 に保存。
* `14 §9 / §5-2`: 投稿編集UIに「AI提案→人が確定」を組み込む。
* `0003`: AIへ渡す画像は派生（EXIF除去済み）に限定。
* APIキーは環境変数（サーバのみ）。Cloudflareのsecretsで管理。

## 将来見直す条件

* volumeが大幅に増えコストが問題化 → 既定を Haiku に固定、または Workers AI 併用を再評価。
* 日本語編集品質で他プロバイダが明確に優位になった場合。
* オフライン/エッジ完結（外部送信を避けたい）要件が強まった場合 → Workers AI 等の内製寄りを再評価。
* モデル世代更新時は最新の能力・価格で既定モデルを見直す（`claude-api` スキル参照）。
