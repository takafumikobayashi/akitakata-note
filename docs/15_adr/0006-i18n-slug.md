# ADR-0006 限定的 i18n / slug 表記

ステータス: **採用（Accepted）** — 2026-06-28 確定（コンテンツは日本語のみ／固定ページのみ将来英語余地、slug は ASCII）

前提: `0001`（Next.js App Router）、SEO/URLは `07 §9`、slug責務は `12 §4-1/§4-2/§4-3/§4-4`、IAは `14 §4/§7`、英語導線は `05`/`07 §9-4`。

## 背景・要件

2つの未決を確定する。

1. **限定的 i18n の実装方式**: コンテンツ本体（投稿）は当面日本語のみ。トップ・About・固定ページに将来の限定的英語対応の余地を残す（`07 §2-3 / §9-4`、`14 §7`）。
2. **slug 表記**: Post / Place / Theme / Season の公開URLを **日本語URL** にするか **ローマ字/英語 slug** にするか。特に `移動・行き方` のような記号・複合語テーマ（`12 §8`）。

## 決定 1: i18n 実装方式

* **next-intl（App Router のロケールルーティング）**を採用。MVP は `ja` のみ有効化し、`/en/...` を後から固定ページ単位で追加できる構造にする。
* **投稿（コンテンツ本体）は翻訳しない**。英語化の対象は固定ページ（About・運営方針・注意）に限定（`StaticPage.locale_fields`、`12 §4-8`）。
* 英語導線（フッター等）を出す場合も非公式性・公私区分を保つ（`05`、`14 §5-7`）。

採用理由: `0001` の Next.js に素直に乗り、ロケール別ルートとメタデータ・OGPの言語整合（`07 §6 / §9-4`）を扱いやすい。MVPで多言語の運用負荷を負わず、将来の限定対応だけ確保する。

## 決定 2: slug 表記 — ASCII を基本とする

公開URLの slug は **ASCII（英語/ローマ字）を基本**とする。表示名（日本語）とは分離し、表示名を変えてもURLは据え置く（`07 §9`、`12`）。

### クローズド語彙（Theme / Season）= 固定の英語 slug

| 種別 | 値（表示名） | slug |
|---|---|---|
| Season | 春 / 夏 / 秋 / 冬 / 通年 | `spring` / `summer` / `autumn` / `winter` / `all-year` |
| Theme | 自然 / 文化 / 日常 / イベント / 食 / 移動・行き方 | `nature` / `culture` / `daily` / `event` / `food` / `mobility` |

* `移動・行き方` → **`mobility`**（`/theme/mobility`）。記号・複合語の%エンコードを避け、URLを安定・可読にする。
* 固定マッピングなので運用負荷は小さい。表示名の文言を変えても slug は不変。

### Post / Place = ローマ字（翻字）slug ＋ 手動編集可

* 場所名・タイトルから**ローマ字へ翻字**して生成（例: 神楽門前湯治村 → `kagura-monzen-toujimura`）。運用者が公開前に編集・上書き可能（`12 §4-1 / §4-2`）。
* 重複時は接尾辞で一意化。表示名（日本語）とは独立。

採用理由

* **URLの資産性・可搬性**: 共有・OGP・サイトマップで%エンコード（`%E7%A7%BB...`）が出ず、安定して読める（`07 §9`）。
* **i18n親和**: 将来 `/en/...` を足しても破綻しない。
* 表示名と分離することで、語彙の文言変更がURLを壊さない。

## 見送り理由

* **日本語URL（例: `/theme/移動・行き方`）**: 日本語話者には直接可読だが、生URL/共有/一部ツールで%エンコードされ、可搬性・安定性で劣る。Theme/Season のような記号入り複合語で特に扱いづらい。→ 可読性を最優先するなら採用余地はあるが、URL資産性を優先して見送り（将来方針転換は可能）。
* **多言語コンテンツ本体（投稿の英訳）**: 個人運営の継続性を損なうため MVP では持たない。

## 影響

* `12 §4-3 / §4-4 / §8`: Season/Theme の slug を上表で確定（ADR 決定事項を反映）。
* `14 §4`: `/theme/mobility` 等の具体 slug が確定。日本語URLの未決が解消。
* `07 §9-4`: 英語固定ページURLは `/en/{slug}` で拡張（next-intl ロケールルート）。
* `StaticPage.locale_fields`（`12 §4-8`）: 固定ページの言語別フィールド方式が確定。

## 将来見直す条件

* 日本語URLの可読性を強く優先したい方針に変えた場合（Theme/Season は英語slug据え置き推奨）。
* 投稿本文の英語対応が必要になった場合（コンテンツ翻訳の運用設計を別途）。
* ロケールが ja/en 以外に増える場合。
